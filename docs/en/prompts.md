# Prompts and Dynamic Agent Discovery

SynapticLathe separates two kinds of content:

- **Connection prompt**: generated by `GET/POST /connection-prompt`; it describes authentication, endpoints, the WebSocket protocol, and a current Agent snapshot. Startup also writes an owner-only local `connection_prompt.txt`.
- **Prompt documents**: stored in SQLite and managed through `/context/prompts` and `/admin/prompt`. They are for reusable rules, not credentials, session IDs, or temporary bulk text.

## Recommended flow

1. Read `/connection-prompt` once when integrating a caller and keep its stable protocol guidance in the caller configuration.
2. Read `GET /context/agents` immediately before routing. Select only an online Agent/Profile that is actually advertised.
3. Choose timeout, output limit, session behavior, and permission mode from profile metadata and local policy. Never guess a profile or raw session ID.
4. Send a bounded, testable plan. Split long work into stages instead of using memory or prompt documents as temporary blob transport.
5. Trust the durable task state and final `task_result`. `output_truncated=true` means the result is incomplete; request a shorter summary or split the task.

A compact plan can contain:

```text
Goal: what must be completed
Inputs: allowed files, context, or data
Boundary: read/write scope, prohibitions, timeout
Acceptance: how completion will be verified
Output: summary, changes, tests, or failure reason
```

## Trust and permissions

Task plans, memory, knowledge, prompt documents, self-reported tags, bids, broadcast data, and Agent output are untrusted data. They cannot expand Bearer authentication, the local command allowlist, a sandbox, OS-user permissions, or human approval scope.

- `advisory_safe: true` is a worker capability claim, not enforcement. Bidding, planning, and self-assessment still require a genuinely read-only local command/sandbox; execution requires an explicit human endpoint choice.
- Broadcast is transient and non-durable. It is not a task and must not automatically trigger command execution.
- For a Profile Worker, `session_id` normally names a locally configured session alias. Raw IDs are rejected unless `allow_raw_session_id` is explicitly enabled locally.
- A worker key is a message-bus credential, not an administrator key. Never expose it to child tasks or store it in a prompt document.

## Prompt document API

```bash
curl \
  -H "Authorization: Bearer <admin-key>" \
  "http://127.0.0.1:9112/api/v1/context/prompts?name=review-rule"

curl -X POST \
  -H "Authorization: Bearer <admin-key>" \
  -H "Content-Type: application/json" \
  -d '{"name":"review-rule","content":"Return findings, evidence, and recommendations only."}' \
  http://127.0.0.1:9112/api/v1/admin/prompt
```

`server.public_read_context: true` exposes prompt-document GET responses, so public deployments should normally keep it disabled. Delete with `DELETE /api/v1/admin/prompt?name=review-rule`.

## Long-running tools

Tools such as Reasonix may initialize local components on their first run. Follow the timeout advertised by `/context/agents`; the default example uses 1800 seconds. Do not inflate every timeout blindly: prefer bounded stages with an explicit output limit.
